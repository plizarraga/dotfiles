# CV rules

Layout rules keep the file parseable by an ATS; writing rules keep it persuasive to the human who reads it next. When the two conflict, layout wins.

## Layout (ATS)

- Single column. No tables, text boxes, images, charts, logos, or skill bars.
- No header or footer: name and contact line sit in the body, top of page 1.
- Full name, then title, then one contact line: city, one phone, plain email, LinkedIn URL. City and country are enough; skip the street address.
- Standard section headers: Professional Summary, Technical Skills, Professional Experience, Certifications, Education.
- Fonts: Arial, Calibri, Georgia, or Times New Roman; 10-12 pt body, 14-16 pt headers. Plain bullets (•, -).
- Dates as `Mon YYYY–Mon YYYY` or `Mon YYYY–Present`, identical everywhere.
- Text-based PDF or DOCX, named `FirstName_LastName_CV.pdf`.
- Reverse-chronological: latest role first.

## Summary

- One paragraph in third person, starting with the name or role ("Pedro is a Senior Software Engineer…"). Pronouns only when natural.
- Three to four sentences, about 70 words.
- Cover: expertise, years of experience, industries supported, role-relevant technical skills, relevant certifications, soft skills, methodologies used. Keep only what the source supports and the JD values.

## Experience

Per role: `Role | Company`, location and dates, bullets, then a stack line (`Environment:` or `Stack:`) with tools, frameworks, and environments.

- Open every bullet with a past-tense action verb (Built, Designed, Migrated, Integrated, Reduced).
- Describe what the person did and what changed: highlights and achievements, not duties. A numeric result belongs in a bullet only when the source states it.
- A company with several projects gets one named sub-block per project, project name in bold, each with its own bullets.
- Each bullet shows how a tool or skill was used, in one or two lines.
- Third person throughout, so the role description starts at the verb: "Migrated the security layer…" replaces "His responsibilities included migrating…".

## Action verbs

- Build: built, designed, developed, engineered, implemented, integrated, configured, automated, architected
- Improve: optimized, refactored, streamlined, consolidated, standardized, upgraded, migrated, reduced, increased
- Lead: led, directed, coordinated, mentored, established, defined, drove, owned
- Analyze: analyzed, diagnosed, evaluated, investigated, identified, resolved, validated, audited
- Collaborate: partnered, collaborated, facilitated, aligned, presented, documented, supported
